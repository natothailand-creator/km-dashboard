# KM Dashboard (เว็บกลาง ข้อมูลเข้ารหัส กรองสิทธิ์ที่เซิร์ฟเวอร์)

เว็บแยกจาก Helpdesk: Next.js 15 + TypeScript ไม่ใช้ฐานข้อมูล ข้อมูลทั้งหมดอยู่ในไฟล์เดียว `data/km.enc` (เข้ารหัส AES-256-GCM)
ที่สร้างจากเครื่องคุณ แล้ว push ขึ้น GitHub เหมือนที่ทำกับ Helpdesk ("auto update data")

## ภาพรวม Flow การท ำงาน
```
[เครื่องคุณ]
 master/KM_Master_Data.xlsx  (Members, Modules, C/P/N, Courses, Settings)
 imports/*.xlsx              (Import_Template ที่ผู้สอนยืนยันคะแนนแล้ว)
        |  npm run data:build   ตรวจแถวผิด -> คำนวณผ่าน/ไม่ผ่าน -> P เป็น N -> ออกรหัสผ่าน -> เข้ารหัส
        v
 data/km.enc  --git push-->  GitHub --> ที่โฮสต์ (Vercel ฯลฯ) + KM_DATA_KEY / SESSION_SECRET ใน Environment Variables
                                                |
                          ล็อกอินอีเมล+รหัสผ่าน -> เซิร์ฟเวอร์กรองข้อมูลตามสิทธิ์ -> ส่งเฉพาะที่มีสิทธิ์เห็นไปที่เบราว์เซอร์
```

## สิทธิ์
| บทบาท (ตั้งในชีต Members) | เห็นอะไร |
|---|---|
| Lead, Manager, Admin | ภาพรวมทีม, Skill Matrix ทุกคน, และหน้า "การเรียนของฉัน" |
| Member | เฉพาะ "การเรียนของฉัน" (เข้าหน้าอื่นจะถูกพากลับ) |

กฎอยู่ที่ `src/lib/access.ts` ที่เดียว ทุกหน้าดึงข้อมูลผ่าน `getScopedData()` ซึ่งกรองฝั่งเซิร์ฟเวอร์เสมอ

## เริ่มใช้งาน (ครั้งแรก)
1. `npm install`
2. `npm run data:keys` แล้วคัดลอกสองบรรทัดไปใส่ไฟล์ `.env.local` (ดู `.env.example`) เก็บสำรองกุญแจไว้ในที่ปลอดภัย: **ถ้า KM_DATA_KEY หาย จะถอดรหัส km.enc ไม่ได้**
3. วางไฟล์ Master ที่ `master/KM_Master_Data.xlsx` (กรอกอีเมลทุกคนในชีต Members และเพิ่มแถว Manager/Admin ต่อท้าย เช่น U025)
4. วางไฟล์ผลสอบ (Import_Template) ไว้ใน `imports/` (ถ้ามี)
5. `npm run data:build` สคริปต์จะ:
   - ตรวจทุกแถวด้วยกฎเดียวกับคอลัมน์ "ตรวจสอบ" ใน Excel ถ้ามีแถวผิด จะหยุดและไม่บันทึกอะไร
   - ข้ามแถวตัวอย่างในเทมเพลตให้เอง
   - เปลี่ยน P เป็น N เมื่อ Post-test ผ่าน (คะแนนรวม = ปรนัย x น้ำหนัก + อัตนัย x น้ำหนัก เทียบเกณฑ์ผ่านของ Module)
   - ออกรหัสผ่านเริ่มต้นให้คนที่ยังไม่มี ที่ `data/initial-passwords.csv` (แจกแล้วลบไฟล์ทิ้ง)
6. `npm run dev` เปิด http://localhost:3000 เพื่อทดลอง
7. ขึ้นระบบจริง: push (รวม `data/km.enc`) และตั้ง `KM_DATA_KEY`, `SESSION_SECRET` ใน Environment Variables ของที่โฮสต์ ค่าต้องตรงกับที่ใช้ตอน build

## ใช้งานประจำ
- ผลสอบรอบใหม่: วางไฟล์ลงใน `imports/` แล้ว `npm run data:build` แล้ว push (ไฟล์เดิมนำเข้าซ้ำจะทับแถวเดิม ไม่สร้างซ้ำ)
- แก้ C/P หรือเพิ่มคน/Module: แก้ Master แล้ว build ใหม่
- **สำรองข้อมูล:** `data/results.json` คือที่สะสมผลสอบทั้งหมด (ไม่เข้ารหัส ห้ามขึ้น GitHub ซึ่ง .gitignore กันไว้แล้ว) ให้สำรองไว้ในที่ที่บริษัทอนุญาต
- ลืมรหัสผ่าน: ลบรายการของคนนั้นใน `data/users.local.json` แล้ว build ใหม่ จะออกรหัสใหม่ให้

## ข้อจำกัดของเวอร์ชันนี้ (ควรรู้)
- **สมาชิกเปลี่ยนรหัสผ่านเองไม่ได้** เพราะเว็บไม่มีที่เก็บข้อมูลที่เขียนได้ รหัสที่ออกให้เป็นสุ่มยาว 14 ตัว (เปลี่ยนต้องออกใหม่แล้ว deploy) ถ้า IT เปิด SSO ภายหลังควรสลับ ส่วนล็อกอินแยกอยู่ที่ `src/app/login/actions.ts` และ `src/lib/session.ts`
- ไม่มี MFA และไม่มีตัวจำกัดจำนวนครั้งที่ลองรหัส (มีแค่หน่วงเวลาเมื่อผิด)
- ข้อมูลใหม่เห็นหลัง deploy ใหม่เท่านั้น (ไม่ใช่ทันที)
- ยังต้องผ่านความเห็นชอบ IT/HR เรื่องเก็บข้อมูลรายคนบนที่โฮสต์ภายนอก และบัญชี Vercel Hobby ไม่เหมาะกับระบบของบริษัท ควรถามว่ามีบัญชี/โฮสต์ที่ใช้ได้หรือไม่ เพราะโค้ดย้ายที่โฮสต์ได้โดยไม่ต้องแก้
- การเข้ารหัสป้องกันข้อมูลใน repo หลุด แต่ใครมี KM_DATA_KEY จะอ่านได้ทั้งหมด เก็บกุญแจแยกจากโค้ด

## สถานะ
ทดสอบแล้วด้วยข้อมูลทดลอง: build ผ่าน, ล็อกอินผิด/ถูก, คุกกี้ปลอมถูกปฏิเสธ, Member เข้า /overview ไม่ได้และไม่เห็นชื่อคนอื่นใน HTML, Lead เห็นทั้ง 25 คน, ไฟล์ km.enc ไม่มีข้อความอ่านออก, ไฟล์นำเข้าที่ผิดถูกบล็อก
ยังไม่ได้ทดสอบบนที่โฮสต์จริง (เช่น การรวมไฟล์ data/km.enc ไปกับ deploy ผ่าน outputFileTracingIncludes ใน next.config.ts) ควรลอง deploy และเปิดล็อกอินทันที

## หน้าจอที่เหลือ (ต่อจากนี้)
/modules/[id] (ก่อน-หลังเรียน, การกระจายคะแนน), /members/[id] (โปรไฟล์ + Timeline), /results, /courses, ตัวกรองไตรมาส/ทีม
นอกรอบแรก: หน้าตรวจอัตนัยในเว็บ, วิเคราะห์ข้อสอบรายข้อ, ปุ่มเตือน/มอบหมาย
